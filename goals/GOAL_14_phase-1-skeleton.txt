  Binding rules - ZONE B applies to most of this goal:
  - EVERY line in a Dockerfile, entrypoint, health endpoint, config validator or shutdown handler
    that exists for a production reason carries a comment saying WHAT BREAKS WITHOUT IT
    (SRC-002 §6.2.6). A Zone B file without those comments is not finished, even if it runs.
  - /health/live returns 200 if the process is alive and TOUCHES NO DEPENDENCY. /health/ready
    returns 503 if Postgres or Redis is unreachable. They behave differently on purpose because
    the load balancer and the container health check treat them differently (SRC-002 §7.4).
  - Config comes from environment variables and the app CRASHES ON STARTUP with a clear message
    naming the missing variable (SRC-002 §7.1). A default that silently papers over a missing
    value is the defect this rule exists to prevent.
  - Logs are JSON to STDOUT with a request id on every line. No log files on disk (§5.4.5, §7.6).
  - Migrations DO NOT run on boot (§7.8). Phase 1 has no migrations, and the entrypoint must
    still be shaped so that adding them later cannot accidentally put them on the boot path.
  - Graceful shutdown on SIGTERM exists from Phase 1 (§7.5), even though there are no locks to
    release yet. The hook is what Phase 4 will hang the lock release on.
  - docker-compose.yml is LOCAL DEVELOPMENT ONLY (§6.1.7) and says so in a comment at the top.
  - Multi-stage build, slim base, final image UNDER 250 MB (§5.4.2). Measure it. Do not estimate.
