  Binding rules:
  - SRC-002 §4.1 fixes React + Vite + TypeScript. It does NOT name a CSS approach. Whatever is
    chosen is a [JUDGMENT CALL] and needs an ADR. A UI component library is a new dependency and
    needs the client's permission first (SRC-002 §13.1).
  - EVERY contrast figure is COMPUTED, not claimed. A contrast ratio written by hand is a number
    nobody ran, and Art VII.1 forbids it. Ship the script that computes them.
  - The seat map is the hardest surface in this product and it is designed here:
      * available / held-by-someone-else / held-by-me / sold / unavailable / wheelchair
        (OPEN-SEAT-02) / couple-seat (OPEN-SEAT-03) - every state distinguishable WITHOUT colour
        alone, because roughly 1 in 12 men cannot separate the obvious palette for this.
      * A large screen may have several hundred seats (OPEN-SCALE-02). The design must survive
        that count on a 375px phone, which SRC-001 §6.1 makes the primary device.
      * State changes arrive by poll every 3 seconds (SRC-002 §8.6.1). A seat going from
        available to sold under the user's finger must be legible, not a silent repaint.
  - Dark and light are both first-class. Every token is defined in both.

  OUT OF SCOPE: writing React components, the PRD, any page layout that is not a token or a
  component specification.

DELIVERABLES
  1. tokens.css - colour, spacing, radius, elevation, motion and type tokens, light and dark,
     as real custom properties the build actually consumes. Not a table in a markdown file.
  2. DESIGN-SYSTEM.md - what each token family is for and when NOT to use it.
  3. contrast.py + CONTRAST.md - every foreground/background pair that the product actually
     uses, computed, in both themes, against both WCAG floors. The markdown is GENERATED and
     says so in a banner.
  4. COMPONENTS.md - specifications for: the seat map and its seven seat states, the showtime
     picker, the movie card, the price summary, the hold countdown, the error banner used when
     a seat is lost mid-selection (SRC-001 §5.2.6), and the empty/loading/error/partial states
     of each.
  5. A named, deliberate visual identity - not a default. State what it is and why it suits a
     cinema booking product.
