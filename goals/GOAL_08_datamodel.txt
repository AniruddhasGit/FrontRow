  Binding rules:
  - datamodel.json is the SPEC OF RECORD. schema.sql, TRACEABILITY.tsv and the seed expectations
    are GENERATED by generate.py. A generated file carries a banner saying so, and regenerating
    must produce no diff. A hand-edit to a generated file is a defect.
  - MONEY IS AN INTEGER IN THE CURRENCY'S MINOR UNIT. No float, no numeric-with-scale that a
    driver will hand back as a float. The currency itself is configuration (Art V.3), so no
    minor-unit ratio is baked into a column name, a comment, or a constraint.
  - The concurrency guard is a SCHEMA OBJECT, not application logic:
      * UNIQUE (showtime_id, seat_id) on the booked-seat relation - the guard that may not be
        waived
      * whatever is needed so that a booking, its seats, and its payment record commit together
        or not at all
      * the idempotency key stored with a UNIQUE constraint, so two simultaneous retries collide
        in the database rather than both succeeding (GOTCHAS, Web & auth)
  - TIME: a showtime is an instant plus the cinema's zone. Never a naive local timestamp.
    OPEN-LOCALE-01's ruling decides the zone; if it was DECLINED, the column exists anyway and
    the value is configuration.
  - PASSWORD RESET NEEDS THREE COLUMNS, NOT TWO. Found by GOAL_05 and easy to collapse:
      email_claimed_at  a worker holds this job. Cleared on failure; the age branch reclaims a
                        dead worker's row.
      email_sent_at     an email actually went out. NEVER cleared.
      used_at           the customer spent the token. Unrelated to sending.
    COLLAPSING ANY PAIR IS A DEFECT WITH A NAME. Reusing email_sent_at as the claim sends a
    SECOND password reset link after a redelivery, because it is never cleared and a stale check
    would reclaim a row whose email already went out. Merging used_at into either loses the
    distinction between spent and delivered. The PRD's P-ACC-07 carries the full table; this is
    here because a data model is where the three would get merged into one "sent" flag.
  - row_label IS AN OPEN ONE-WAY DOOR. DO NOT DECIDE IT HERE (OPEN-SEATLABEL-01, reserved).
    It is unique per screen and unnormalised, so C12 and c12 are two seats a person reads as
    one name - and the label is printed on the receipt and read aloud at the door. Do NOT
    apply the lookup-name normalisation to it by analogy: that rule is lower(trim()), this one
    would have to be upper-case, so it changes what is STORED. P-ADM-14 freezes row_label once
    a showtime exists, so a rule applied later cannot correct a row already written. Model the
    column, cite the open row, and leave the normalisation unruled.
  - AUDIT: SRC-001 §7.6 requires answering "who booked this seat and when" for ANY seat, at any
    time. That is a schema requirement, not a logging preference.
  - FOUR roles, not five (SRC-003 C-1, ruled 2026-08-14, PROVISIONAL): guest, customer,
    manager (read-only, scoped to assigned screens), admin. The cinema-staff role is GONE
    (SRC-001 erratum E-1). This goal file said FIVE before SRC-003 existed; a schema built
    from the old line would carry a role nothing can ever populate.
  - Keep the cinema entity even though there is one row, and keep a booking status and
    cancelled_at that no v1 endpoint exposes (SRC-001 §6.6 - excluded is not blocked).

CORRECTIONS APPLIED 2026-08-23
  This contract was written before the nine Article X rows filed on 2026-08-22. Five of them land
  on columns THIS goal defines, so they are restated here as binding constraints. All five are
  RESERVED - the schema models the column and cites the row; it never decides the question.

  - OPEN-RESETTOKEN-01 (reserved: SECRETS). The password-reset flow AS SPECIFIED CANNOT BE BUILT:
    three PRD passages are jointly unsatisfiable - the token is never stored, the token never
    travels in the queue, and the worker must render a link containing the token. Nothing holds
    the 43 characters. THE SCHEMA MUST NOT RESOLVE THIS. Adding a plaintext token column, or a
    payload column on outbox_message wide enough to be used for one, decides a reserved question
    about credential handling by making one of the three resolutions cheap. Model token_sha256,
    cite the row, and leave the flow unbuildable until the client rules. This does NOT relax the
    three-column rule below: claim, sent and used are about worker mechanics, not about where the
    plaintext lives, and they are still three columns.

  - OPEN-REFCHAR-01 (reserved: IRREVERSIBLE, expires Phase 4). The booking-reference alphabet
    keeps the confusable pairs 2/Z, 5/S, 8/B, 6/G and carries no check character, and the
    reference is transcribed BY EYE at a door with no software in the path. Model the column and
    its uniqueness; do NOT narrow the alphabet, add a check character, or bake either into a
    CHECK constraint. A reference already issued cannot be re-cut.

  - OPEN-SEATALPHA-01 (reserved: IRREVERSIBLE, expires Phase 2). Sits BESIDE OPEN-SEATLABEL-01 on
    the same column. SEATLABEL is about normalising case; SEATALPHA is about whether the letter I
    may appear at all. Both are unruled and neither may be expressed as a constraint.

  - OPEN-DUPREF-01 (reserved: PRODUCT). Nothing rules what happens when one reference is presented
    twice at the door, and no audit action exists for the incident. This is a schema question only
    in that a redemption or admission column would answer it. DO NOT ADD ONE.

  - OPEN-HOLDRECOVER-01 (reserved: SCOPE). A live hold is Redis-only and deliberately has no
    database row. Do not model holds. A holds table would make the reserved question answerable
    and would put the seat guarantee in two places, which is exactly what the two-system design
    already rejects.

  TABLE NAMES ARE INHERITED, NOT CHOSEN. GOAL_07's 200 acceptance criteria already contain SQL
  naming these fifteen relations: users, cinema, screen, seat, movie, showtime, showtime_seat,
  booking, booking_seat, payment, idempotency_record, password_reset_token, outbox_message,
  receipt_dispatch, audit_log. A rename here silently breaks criteria in 200 cells that nothing
  in the repo cross-checks. If a name is WRONG, changing it is a deliberate act that updates the
  Bible in the same commit - never a quiet improvement.

  OPEN-LOCALE-01 IS RULED, not pending. The zone is Asia/Kolkata, currency INR, minor-unit ratio
  100 (SRC-003). The line below reading 'if it was DECLINED' predates that ruling. The ratio
  remains configuration and is never baked into a column name, comment or constraint.
