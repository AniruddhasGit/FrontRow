> **Compressed per SRC-004 R-1.** The client chose one lighter pass over `GOAL_09`–`GOAL_13`. This
> file and the ledger were written in that pass. Review depth was reduced; no green was faked and no

## The rules

- **The ledger is generated.** `py "docs/10 EngineeringLedger/generate_ledger.py"` rewrites it.
  **Only `Status` and `StatusNote` are hand-edited**; the generator keys them by `ID` and carries
  them across every regeneration. Any other hand edit is undone by the next run, and
  `--check` fails until then.
- **`/ss` anchors to header names, never to positions.** Column order may change. The awk snippet
  in `~/.claude/commands/ss.md` was run against this file and its output is in the GOAL_12 gate
  output.
- **Status law:** `Backlog` · `InProgress` · `Done` · `Blocked`. A row is never quietly `Done`:
  `--check` fails a `Done` row whose `EvidencePath` folder does not exist. A `Blocked` row with an
  empty `StatusNote` fails too — the reason lives in the row.
- **Two rows with overlapping `OwnedPaths` are never worked at once.** The generator puts them in
  different `Wave`s, and `--check` proves no wave contains such a pair.

| `Type` | `Epic` and `Story` are copied from the Bible. `Task` is a Phase 1 unit the generator adds (below). | `Epic` `Story` `Task` |

| `ParentID` | Bible parent for a story; for a task, the Bible story (or epic) it decomposes. Empty for an epic. | a row `ID` or empty |
| `Epic` | The epic the row rolls up to. For an epic, itself. | an `E-` id |
| `Lane` | The lane code from the id. | `ACC` `ADM` `BRW` `PAY` `RPT` `SCP` `SEA` `TKT` `XCT` |
| `Title` | Copied from the Bible, or the task's title. | text |
| `AcceptanceCriteria` | Copied verbatim from the Bible. For a task, the `GOAL_14` DoD lines it must satisfy plus a pointer to the parent story. Empty for an epic. | text |
| `Priority` | Copied. Tasks are `MustHave` because `SRC-002 §12.2` mandates Phase 1. | `MustHave` `ShouldHave` `CouldHave` |
| `Estimate` | Copied story points. **Empty for epics and for tasks** — nobody estimated the tasks and the generator does not invent a number. | `1` `2` `3` `5` `8` `13` or empty |
| `Milestone` | The phase, `SRC-002 §12` as revised by `SRC-003` (table below). Copied from the Bible; tasks are `1`. | `1`–`8` |
| `Status` | **Hand-edited. Preserved across regeneration.** Every row is `Backlog` at generation. | `Backlog` `InProgress` `Done` `Blocked` |
| `StatusNote` | **Hand-edited. Preserved.** Required when `Blocked`; the reason and who unblocks it. | text or empty |
| `DependsOn` | Copied, space-separated. A dependency on an epic means that epic's rows in the same or an earlier milestone. `--check`: every id resolves, none sits in a later milestone. | row ids |
| `Labels` | Copied from the Bible's vocabulary; a task takes the labels its unit needs. | `backend` `frontend` `data` `infra` `security` `concurrency` `money` `email` `a11y` `test` `scope-guard` |
| `Persona` | Who the row's behaviour is for, from the role words its text uses (`ADM` adds `admin`, `RPT` adds `manager`). `operator` = the client running the system, when no role is named. Space-separated. | `guest` `customer` `manager` `admin` `operator` |

| `Wave` | Parallel-work slot. Rows in one wave have disjoint `OwnedPaths` and no unmet dependency inside the milestone; a wave never spans two milestones; wave numbers rise with milestone. | positive integer |

| `NegativeCaseIDs` | Same, from `docs/09 NegativeTesting/SIT_NegativeCases.tsv`. **Empty at generation; the file did not exist.** | case ids |
| `OpenRefs` | OPEN ids the row's description, criterion or source cites that are **still open** in `CONSTITUTION.md` Article X (X.0–X.0g) and not ruled by `SRC-004`. **Escalate, never invent** while this is non-empty. | `OPEN-…` ids |

| `EvidencePath` | The folder where the row's gate output goes when it is done. `--check` refuses `Done` without it. | `docs/10 EngineeringLedger/evidence/<ID>/` |
| `SourceRef` | Copied. Tasks cite `SRC-002` clauses and `GOAL_14`. | citations |
| `GoalRef` | The goal file that builds the row. Only Phase 1 has one (`GOAL_14`); every later phase reads `unwritten (phase n goal)` until its goal exists. | `GOAL_nn` or that phrase |

## What `--check` proves

| Check | Fails when |
|---|---|
| `regenerate-no-diff` | the file on disk differs from a fresh generation in any byte (Status/StatusNote are preserved, so only a hand edit elsewhere or a changed input fails it) |
| `count-equals-bible` | ledger `Story` rows ≠ Bible stories, or ledger `Epic` rows ≠ Bible epics |
| `status-law` | an illegal Status, a `Blocked` with no note, a `Done` with no evidence folder |
| `case-ids-resolve` | a SIT or negative case id does not exist in its file |
| `depends-no-later-phase` | a dependency does not resolve, or sits in a later milestone |
| `wave-owned-paths-disjoint` | two rows in one wave have overlapping `OwnedPaths` |
| `wave-within-milestone` | a wave holds rows of two milestones |
| `header-names` | a column `/ss` anchors on is missing, or a header name repeats |
| `enum-legality` | a generated enum cell holds an illegal value |

Red-proofed in the GOAL_12 session: a hand-edited `Title` failed `regenerate-no-diff` (exit 1); a
`Blocked` row without a note and a `Done` row without evidence each failed `status-law`; a
regeneration kept both hand-set Status values. The ledger was then restored and passed.

## Known weaknesses — read before trusting a cell

- **`OwnedPaths` is `ASSUMED`.** `docs/07 Architecture/` had no module map when this was generated,
  so paths are the `SRC-002 §11` shape split by lane, plus title keywords for the cross-cutting
  lane. When `GOAL_09` publishes a module map, replace `LANE_PATHS` and `XCT_RULES` in the
  generator with it and regenerate. The cost of the coarse map is visible: **152 waves for 209 work
  rows** — milestone 2 alone needs 42 because its `data` stories all own `backend/migrations/` and
  the `ADM` lane shares one folder. A finer map would parallelise more; the coarse one is safe, not
  fast.
- **`NegativeCaseIDs` is empty** because `docs/09 NegativeTesting/SIT_NegativeCases.tsv` did not
  exist at generation; "zero dangling" is true and **vacuous** for that column. `SITCaseIDs` was
  filled from `GOAL_10`'s files, which were being written in parallel in the same compressed pass —
  **regenerate after `GOAL_10` and `GOAL_11` close**, and `--check` will report the diff until then.
- **`Persona`, `Classification`, `Risk` and `TestTrustLevel` are keyword rules**, not readings. The
  rules are in the generator, so a disagreement is fixed there, not in the cell.
- **The census grade per story is not stored anywhere**, so `census-named` marks only the stories the
  census text names; a story the census graded `WRONG` without naming it reads `spec`.
- **`OpenRefs` reads `CONSTITUTION.md` Article X as written.** `SRC-004` ruled four rows after it was
  written; those are subtracted and shown in `RuledRefs` instead.
